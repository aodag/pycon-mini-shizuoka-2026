** argparseのサブコマンド
- サブコマンド作るくらいなら、entrypointになるモジュールを別にしとけとは思いますが
- ~~/bin~ にファイル1つで置いときたいという趣旨があるので
- add_subparsersでサブコマンド向けのパーサーを追加
- サブコマンド向けのパーサーにサブコマンドを追加してさらにその引数を追加
- サブコマンドごとに処理を分岐する方法がいくつか
  - subparserにset_defaultsで処理関数を渡す
  - add_subparsersのdestでサブコマンド名を受け取るようにする

** argparseでサブコマンド その１

- add_subparsersのdestでサブコマンド名を受け取るようにする
- enumつかいたくなるけど、あんまり良い方法思いつかない

#+begin_src python
  subparsers = parser.add_subparsers(required=True, dest="action")
  init_parser = subparsers.add_parser("init")
  run_parser = subparsers.add_parser("run")
  args = parser.parse_args()
  match args.action:
      case "init":
          init(args)
      case "run":
          run(args)
      case _:
          parser.print_help()
#+end_src

** argpaseでサブコマンド その２

- サブパーサーのset_defaultsで処理関数を渡しておく

#+begin_src python
  subparsers = parser.add_subparsers(required=True, dest="action")
  init_parser = subparsers.add_parser("init")
  init_parser.set_defaults(func=init)
  run_parser = subparsers.add_parser("run")
  run_parser.set_defaults(func=run)
  args = parser.parse_args()
  args.func(args)
#+end_src

** これだけ知っとけ正規表現：テキスト処理の飛び道具
- ~.~ :任意の一文字にマッチ
- ~*~ :直前の正規表現0個以上にマッチ
- ~|~ : どちらかの正規表現にマッチ
- ~[]~ :囲んだ中の文字のどれかにマッチ
- ~[^]~ :囲んだ中の文字のどれか以外にマッチ
- ~^~ :文字列の先頭
- ~$~ :文字列の終端
- ~()~ :囲んだ正規表現で ~*~ とかの対象
- ~\d~, ~\w~, ~\s~ : 数字にマッチ, 表示可能な文字にマッチ、スペースや空白文字にマッチ

** パイプアンドフィルターではgeneratorを使おう
- listなどにしてしまうとforループが終わるまで処理が進まない
- EOFがくるまでforループが終わらない
- 特に標準入力を読むときはEOFを待ってから処理するとパイプアンドフィルターが詰まる

** generatorへの入力: yieldが返す値
- ちょっとずつ処理する = ちょっとずつ値が帰ってくるだけではない
- ちょっとずつ入力する
  - ~yield~ で値を受け取る
- 加算器の例
#+begin_src python
  def accum():
      v = 0
      try:
          while True:
              v += yield
      except GeneratorExit:
          return v
#+end_src

- ~GeneratorExit~ なんてどこで発生するんだよ！？
  - ~yield~ からです

** generatorへの入力： sendとcloseでアキュムレータ

- sendメソッドで値を送るとgeneratorの中でyieldが返す値になる
- closeを呼ぶと中でGeneratorExit例外が発生するのでexceptしてreutrnさせる
#+begin_src python
  >>> a = accum()
  >>> a.send(None)
  >>> a.send(13)
  >>> a.send(47)
  >>> a.send(100)
  >>> a.close()
  160
#+end_src

* エラー処理
** エラーが起きたら
- とりあえずなにもせずにインタプリタに任せる
- 例外のエラーメッセージ出してくれるし、終了ステータスもエラーになるし
** 自分で例外処理する？
- これじゃだめなの

#+begin_src python
  def main():
      try:
          process():
      except Exception as e:
          logger.exception(e)
              
#+end_src

- プロセスの終了ステータスが正常終了になってしまう
  - え？このAPIはエラーメッセージがレスポンスボディに入ってるのに200 OK返すんですか？
** 自分で例外処理するなら
- 自分でやるなら ~sys.exit(255)~ で異常終了にしましょう
#+begin_src python
  def main():
      try:
          process():
      except Exception as e:
          logger.exception(e)
          sys.exit(255)
#+end_src
